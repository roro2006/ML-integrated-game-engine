# ADR-0011: Asset pipeline and shader workflow

- Status: Accepted
- Date: 2026-09-15

## Context

Open decision §16.8 (asset import approach and shader workflow). Assets are
primitive-first Blender models plus carefully tracked CC0 assets, targeting
integrated graphics with shared materials and atlases.

## Decision

**Models: glTF source, baked engine format.**

- Blender exports glTF/glb into `assets/source/` (tracked for provenance, not
  shipped).
- An offline bake step converts glTF into an engine-owned binary format under
  `assets/models/`: interleaved vertex buffers, index buffers, bounds, and
  material references, laid out for direct upload.
- The shipped runtime loads **only** the baked format. No glTF importer ships
  in the game binary.
- The bake is deterministic: sorted directory traversal, stable ordering, and a
  content hash per asset recorded in the asset manifest alongside source and
  licence metadata.
- The bake **validates winding** and flips inconsistent triangles. `MeshData`
  carries positions, normals, UVs, and indices but records no winding or
  shading intent, so the counter-clockwise-from-outside convention currently
  lives only in documentation and in the procedural primitives' tests. Those
  primitives are generated by code we control; imported glTF is not. With
  back-face culling on, an inside-out mesh is silently invisible rather than
  obviously wrong, which is an expensive thing to debug at scene-assembly time.
- The bake step is a workspace tool (`cargo xtask bake` or equivalent), not a
  build script, so it never runs implicitly during a normal build.

**Shaders: WGSL, hot-reloaded in development.**

- Shaders are authored as WGSL files under `assets/shaders/`, named
  `snake_case.wgsl` (`lit.wgsl`, `debug_line.wgsl`). This is a deliberate
  exception to the project's lowercase-kebab-case filename rule, confirmed
  2026-09-16: that rule governs human-authored content addressed by stable ID,
  while shaders are code referenced from Rust by constant and `include_str!`,
  and follow WGSL/Rust naming instead.
- Debug builds load them from disk and hot-reload on change, reporting
  compilation errors to the debug overlay without exiting.
- Release builds embed shader sources at compile time, so a shipped build
  cannot fail because a file is missing or edited.

## Consequences

- Load times stay fast and predictable, and the runtime stays small — both of
  which matter for the low-spec target.
- There is a build step to remember. Forgetting to re-bake after editing a
  model is the obvious foot-gun; the content hash in the manifest makes it
  detectable, and the loader should warn when a baked asset is older than its
  source in development builds.
- The baked format is versioned like every other content format, and needs a
  version bump plus a re-bake when the layout changes.
- Shader hot-reload materially speeds up renderer iteration in M3, which is
  when most shader work happens.

## Alternatives considered

- **Load glTF at runtime**: no build step and simpler iteration, at the cost of
  shipping an importer and slower, less predictable loads.
- **Custom Blender exporter**: total format control, but a real tooling project
  that breaks whenever Blender changes.
- **Precompiled SPIR-V instead of WGSL**: faster startup and offline
  validation; rejected for now because WGSL keeps the toolchain simple and
  wgpu handles compilation. Revisit if shader compilation shows up in startup
  profiles.
